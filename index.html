tools I build while learning how things work

whoami :

I write tools around Bitcoin, Jai, C, and parsers because I learn better when I can test ideas directly.

Most of these projects started with a simple frustration: I wanted to understand how a script, file format, compiler, or protocol component worked by building something around it.

Some of the tools are practical, some are mostly learning exercises. I keep both around because they show what I was trying to understand at the time.

> building, breaking, rewriting; mostly around Bitcoin Script, Miniscript, Jai, C, and parsing.

what i work on :

Bitcoin Script and Miniscript, blockchain data formats, small C and Jai tools, compiler/analyzer interfaces, and experiments that help me learn how things work internally.

how i build :

I like tools that are small enough to understand, local when they can be, and honest about what they are doing. I do not mind complexity, but I want to be able to inspect it instead of only trusting the interface.

projects :

  • Bitcoin Timeline

    what: curated browser timeline of Bitcoin protocol, consensus, market, culture, and ecosystem milestones.

    why: I wanted a dense reference that keeps protocol history inspectable by block height instead of scattered across articles and release notes.

  • BASM Studio

    what: web interface for BASM, my Bitcoin Assembly compiler/analyzer written in Jai.

    why: I wanted a practical UI to write BASM programs, test the compiler, inspect the generated script, and iterate faster.

  • btcdebugger

    what: browser frontend for btcdeb.

    why: I wanted to use btcdeb through a web UI and make script execution easier to inspect while stepping.

  • Miniscript Lab

    what: Sipa's Miniscript JS bindings in a browser frontend.

    why: I wanted to use Miniscript in a frontend and learn how policies become Miniscript, scripts, and possible spending paths.

  • coreparse

    what: C API for reading and parsing a Bitcoin Core datadir.

    why: I wanted to inspect node data directly instead of treating Bitcoin Core's files as a black box.

  • CTB

    what: stb-style header-only C toolbox.

    why: small reusable C utilities, kept simple enough to understand, copy, and drop into experiments.

  • BIP39 Mnemonic Generator

    what: Python script for generating mnemonic seeds.

    why: a learning exercise to understand mnemonic generation instead of treating seed words as magic output from a wallet.

motivation :

The main point is learning how things work. Building a tool forces me to deal with the edge cases, data formats, assumptions, and failure modes.
